https://gustnel1122-pixel.github.io/mumutori-offline-pages/

기존 공간 사진과 디자인 제안, 캔버스에 그리는 회전 가능한 3D 공간, 편집 가능한 실행 체크리스트와 준비물을 모은 정적 페이지입니다.

- 왼쪽 고정 목차, 작은 화면의 접이식 목차
- 3D 드래그·터치·키보드 회전, 확대/축소, 시점 전환
- 레퍼런스에서 제공된 실제 판매 상품 16종 진열
- 할 일·준비물 추가/수정/삭제와 분류 관리, 담당·중요도·기한·선행 작업 편집
- 브라우저 자동 저장, 사용자 정의 목록을 포함한 JSON 백업/복원
- 전용 공유 링크를 열면 로그인 없이 Firebase에 준비 기록 동기화
- 구매 목록 모든 묶음의 항목별 판매처 링크·메모 자동 저장과 새 항목 추가

매장 준비 목록은 `#preparation` 하나로 엽니다. 구매 81개와 준비표의 같은 항목을 합쳐 기본 원본 124개를 52개 용도 묶음으로 표시합니다. 원본 ID·링크·메모·체크는 삭제하지 않고 각 줄의 기존 기록에서 확인합니다. 선택용 상품은 ‘후보 n개’ 안에서 고르고, ‘안 함’ 항목은 숨길 뿐 삭제하지 않습니다. 기존 `#buylist`·`#inventory` 주소도 새 목록으로 연결됩니다.

‘지금 작성하는 사람’에서 사장님 또는 다희를 고른 뒤 하자·보류·안 함을 누릅니다. 작성자 이름은 본인 선택값이며 로그인 인증을 뜻하지 않습니다. 상태 칩 메뉴는 미정·장바구니·결제완료·배송중·도착·설치 끝·안 삼입니다. 안 삼과 결정 안 함은 함께 바뀌며, 다시 하자/보류를 고르면 안 삼 이전 상태로 돌아갑니다. 안 삼에서 다른 상태를 고르면 하자로 바뀝니다.

기본 목록은 오픈 필수 19줄, 나중에는 33줄입니다. 진열 가구·판매 상품 확인·결제·기본 포장·간판·레터 코너·청소를 우선하고 꾸밈·추가 도구는 접었습니다. 필수로 올리기/나중에로 옮기기는 공유 기록으로 저장합니다. 설치 끝은 ‘끝’ 묶음에 접으며 카드 단말기는 10/26 사장님 확인으로 서류·신청 완료를 반영했습니다. 옛 단말기 메모는 기존 기록 안에 남깁니다.

살 것→미정, 주문함→결제완료, 도착·설치 끝→설치 끝으로 읽습니다. 원본 상세와 옛 메타데이터는 읽기만 할 때 다시 쓰지 않습니다. 새 변경 시 기존 문자열 내부에 상태·필수 여부를 저장하며 Firebase 경로와 7필드 정의/2필드 체크 구조는 그대로입니다.

상단 장바구니/결제완료 수는 전체 목록의 해당 상태 수입니다. 남은 것은 필수 중 설치 끝·안 삼을 제외합니다. 결제완료 합계는 결제완료·배송중·도착·설치 끝의 입력 예상 총액 합계이며 실제 결제 장부가 아닙니다. 안 함은 제외하고 미입력 금액 개수를 표시합니다. 원가·계좌·개인정보는 입력하지 마세요.

`preparation-data.js`는 화면 묶음, `preparation-state.js`는 기존 정의의 detail 문자열 안에서 결정·의견·선택·예상 금액을 보관합니다. 기존 링크 구분과 메모 원문은 그 안에서 그대로 보존하며, 기존 7개 정의 필드·2개 체크 필드 및 Firebase 경로를 바꾸지 않습니다. 준비물 정의는 편집하는 항목만 저장합니다. 저장 범위 초과·손상된 기록은 오류로 멈추며 자르거나 덮지 않습니다. 예전 팔시보 메모 이전과 서버 확인 후 이전 완료 처리는 유지합니다.

화면: `preparation-view.js`·`preparation.css`·`preparation-grid.css`. 데스크톱과 휴대폰 모두 격자 표가 기본이며, 휴대폰에서는 가로로 밀어 봅니다. 머리줄과 체크·사진·이름 3개 열은 고정됩니다. 카드 보기는 버튼으로 전환합니다. 체크는 결제완료, 해제는 미정이며 배송중·도착·설치 끝도 체크된 상태로 표시합니다. 기존 3D·사진·전체 메모·예산 화면은 별도 기능으로 유지합니다. 검증: `node --test tests/*.test.cjs`.

기존 `preparation-photos.js`의 판매처 주소 8줄에 더해 `preparation-examples.js`가 기존 기본 18줄 전체에 예시 상품 또는 보유품·배치 참고 사진, 원본 링크, 참고 표시가와 출처를 제공합니다. 사진에 ‘예시’를 표시하며 공개 검색 화면·기존 기록 가격은 현재 결제 가격으로 보장하지 않습니다. 보유품과 주문제작·입고 확인 줄에는 임의의 구매가를 만들지 않습니다. 예시는 상품 선택이나 공유 기록에 자동 저장하지 않으며 합계에도 넣지 않습니다. 사용자 사진(명시적으로 비운 사진 포함)을 우선하고, 다른 후보 상품을 선택하면 원래 예시가 그 상품의 사진처럼 나오지 않게 숨깁니다.  이미지 파일을 저장소에 복사하지 않습니다. 상품을 고른 줄은 그 상품의 사진만 자동 표시합니다. 사진 확대·여러 장 보기·대표 사진 선택과 주소 추가를 지원합니다. `preparation-images.js`가 휴대폰 파일을 JPEG로 다시 인코딩해 메타데이터를 제거하고 가로·세로 400px, 80KB 이하로 줄입니다. 기존 공유 정의의 detail 6,000자 제한도 지켜야 하므로 실제 파일은 남은 공간에 맞춰 수 KB로 더 작게 압축합니다. 공간이 부족하면 원본 메모를 자르지 않고 사진 주소를 사용하도록 안내합니다. 사진 정보는 같은 detail 메타데이터에 저장하고 기존 Firebase 계약을 유지합니다. HTTP/HTTPS 주소와 크기 검증된 JPEG 데이터만 허용합니다.

전용 공유 링크를 열면 Google 로그인 없이 함께 수정할 수 있습니다. 왼쪽 목차 아래 ‘공유 링크 · 저장 상태’의 ‘공유 링크 복사’로 같은 링크를 전달합니다. 링크를 가진 사람은 준비 기록 전체를 보고 수정할 수 있으므로 함께 작업할 사람에게만 전달하세요. 공유 키가 없는 일반 주소는 기기에만 저장합니다. 공유 키는 공개 소스나 README에 포함하지 않습니다.

처음 방문한 기기는 공유된 기록을 자동으로 불러옵니다. 기존 기기에 따로 수정한 기록이 있으면 이어 쓸 기록을 선택합니다. 동시 변경이 감지돼도 기록을 자동으로 덮어쓰지 않습니다. 연결 전 기록은 기기에 백업되며 JSON으로 받을 수 있습니다. 체크리스트와 준비물의 항목·분류·삭제, 완료 상태, 메모, 오픈 예정일을 함께 동기화합니다.

연결 전과 오프라인에서는 기기에 저장됩니다. 서버 저장 완료 표시를 확인한 뒤 페이지를 닫고, 중요한 기록은 JSON으로도 백업하세요. 고객 편지 본문이나 배송 주소는 이 준비 페이지에 입력하지 마세요.

GitHub Pages의 main 브랜치 루트에서 게시합니다. 별도 빌드와 외부 3D 라이브러리는 필요하지 않습니다. `index.html`이 진입점입니다. 정적 스크립트나 스타일을 바꾸면 HTML의 버전 쿼리도 갱신해 이전 캐시를 방지하세요.

공간의 비례와 집기는 실측 전 제안이며, 상품 사진은 진열 예시입니다. 현재 재고·가격·사입 수량을 확정하는 자료는 아닙니다. 폰트 라이선스와 상품 출처는 assets 아래에 있습니다.

로그인 없는 공유는 전용 경로에만 적용하며 이전 소유자 전용 기록은 별도로 보존합니다. 새 공유 링크로 접속해야 같은 기록을 함께 수정할 수 있습니다. 이전 Google 연결 페이지와 새 공유 경로 사이의 양방향 복제는 하지 않습니다.

10/27 사이드 필수 항목 1줄을 추가했습니다(2개 · 하자 · 미정). 판매 페이지를 읽지 못해 상품명·가격·사진은 확인 필요로 두고 추적 꼬리 없는 상품 링크만 제공합니다. 기존 사용자 수정값과 구매 상태는 보존합니다.

## 2026-10-27 공동 작업판 (offline-shared-20261027)

운영 첫 화면을 현수·다희 공동 작업판으로 개편했습니다. `#today` 담당별 다음 할 일, `#production` 자리별 제작물 8칸, `#preparation` 기존 통합 구매 목록, `#resources` 도면·확정 기록, `#ai-guide` AI 안내, `#notes` 백업, `#previous-records` 과거 자료 순서입니다. 오픈 표시는 2026-11-01(일)이며 옛 저장 openingDate는 보존합니다.

제작물은 `production-data.js` 공개 기본값을 보여주고 편집한 칸만 기존 `definitions.inventory`의 7필드 정의와 `inventory`의 2필드 상태에 저장합니다. 안정 ID는 `place-sign`, `place-banner`, `place-glass`, `place-center`, `place-arch`, `place-teal`, `place-counter`, `place-other`입니다. detail 문자열은 `[[MUMUTORI_PRODUCTION:1]]` 뒤 JSON입니다. 기존 항목·메모·사진·체크·예산과 Firebase 경로·규칙은 변경하지 않습니다. 제작물 전용 항목은 구매 합계에서 제외합니다. 초기 담당은 시작용 배정이며 페이지에서 변경할 수 있습니다.

`shared-merge.js`는 마지막 확인 상태를 기준으로 다른 칸·필드의 동시 수정을 합칩니다. CAS가 실패하면 최신 값을 읽어 합친 뒤 다시 조건부 저장합니다. 같은 필드/제작물 내용의 충돌과 삭제·편집 충돌은 기존 기록 선택창으로 멈추며 양쪽을 백업합니다. 공유 연결 전 서로 다른 기기 기록을 자동 병합하지 않습니다.

AI는 공개 HTML의 배포 기준, 공유 화면의 실시간 텍스트, `현재상태 파일 받기`로 만든 읽기용 Markdown을 구분해야 합니다. 공개 일반 주소는 다른 기기의 Firebase 값이 아니며 공유 링크가 필요합니다. 파일은 각 칸의 Drive 폴더, 변경 요청은 요청/에 칸 ID·현재값·새값·근거를 적고 담당 반영 후 결과/를 확인합니다. 공유 키를 공개 코드·요청·스냅샷에 넣지 않습니다.

Drive 자동 스냅샷 설치는 연결 브라우저 시간 초과로 미완료입니다. 초기 기준 스냅샷과 수동 복사/다운로드는 제공하며, 자동 갱신을 확인하기 전에는 파일을 실시간 서버 값으로 간주하지 않습니다. Apps Script 설치용 코드는 비공개 협업 자료에 보관합니다.

검증: `node --test tests/*.test.cjs` (66개). 격리 브라우저 PC/390px, 편집·새로고침, 가로 넘침 없음. 실운영 공동 데이터에 가짜 시험행을 쓰지 않습니다.

### Drive 파일 업로드 연결

프런트엔드와 `apps-script/OfflineOrders.gs`·`OfflineUpload.html` 구현은 준비됐습니다. **Apps Script 설치/배포와 실제 Drive 시험이 완료되기 전에는 파일 업로드 완료로 보고하지 않습니다.**

1. 소유자의 기존 Apps Script 소스·설정·배포 버전을 비공개 백업합니다. 기존 doGet·메일/장부/로그인 알림 함수 및 트리거를 보존합니다.
2. 두 파일을 추가하고 `doGet(e)`에서 검증된 오프라인 공유 키 요청만 `offlineOrdersGet(e)`로 전달합니다. 기존 다른 키/형식의 라우트는 유지합니다. 주소는 `/exec?k=…`이며 `/exec/추가경로`는 사용하지 않습니다.
3. 비공개 Script Properties `OFFLINE_SHARED_URL`에 기존 공유 링크를 설정합니다. 값은 소스·로그·공유 보고서에 쓰지 않습니다. `installOfflineOrders()`는 그 키를 `OFFLINE_SHARE_KEY`로 재사용하고, 요청 큐 파일과 자신의 15분 내보내기 트리거만 생성합니다. 기존 다른 트리거를 바꾸지 않습니다.
4. 소유자 실행/익명 접근 웹앱 배포를 확인하고 같은 배포의 새 버전으로 갱신합니다. 기존 Drive·UrlFetch 범위를 재사용하며 새 범위가 필요하면 소유자 권한 동의가 필요합니다.
5. 페이지에서 파일 올리기 → 연결 창에 비밀값 없는 `/exec` 주소만 저장합니다. 실제 키는 공유 링크에서 팝업에만 전달됩니다. 서버가 키·파일·크기·조각 위치를 검증합니다. 2MB씩 Drive resumable 전송, 개당 최대2GB, 파일 지문+서버 오프셋으로 이어 올리기. 최종 Drive 파일 크기를 확인하고 CAS로 항목에 1회 연결합니다. 팝업 메시지는 보조 알림이며 중복 첨부를 막습니다.
6. 작은 PNG/PDF와 50MB 이상 PSD 또는 ZIP을 실제로 올리고 중단/이어 올리기·두 기기 반영·폴더·바이트 크기를 다시 읽어 확인합니다. 가짜 구매 기록은 만들지 않습니다. 실패 파일은 사용자가 처리하며 자동 삭제하지 않습니다.

파일 저장 위치는 사장님 Drive `다희/첨부/`. 소스 안의 폴더 ID는 접근 권한이 아닌 대상 식별자이며 원본 파일의 공유 권한을 전체 공개로 바꾸지 않습니다. 익명 업로드와 Drive 원본의 익명 열람은 별개입니다. 이미지가 3D에 직접 표시되려면 브라우저가 이미지로 읽을 수 있는 URL이어야 하며, Drive 보기 페이지 링크는 결과 파일 링크로 보관합니다.

### 목업 예약 연결

`exportOfflineOrderQueue`가 실제 공동 요청 목록을 비밀값·가격·원가·전체 노트 없이 지정한 Drive 큐 파일에 내보냅니다. 큐의 ready/내용과 실제 서버 값을 확인한 뒤 ChatGPT 09:00·18:00 Asia/Seoul 예약을 등록합니다. 예약 환경에서 이미지 생성/파일 저장/페이지 갱신을 수행할 수 있는지 첫 회차를 검증해야 하며, 지원하지 않으면 완료로 표시하지 않고 이 Work 대화의 처리 대기로 남깁니다. 현재 코드가 설치되지 않은 상태에서 예약만 만들어 자동 제작이 가동된 것으로 보고하지 않습니다.

목업 처리 화면의 ‘처리 기록’에서 결과 URL·상태와 3D의 식탁보/현수막/유리벽/간판 그림 적용을 기록합니다. 가구 위치·크기 수정은 cm 단위이며 평면 시점과 3D 시점에 함께 반영됩니다. 원본 실측 도면은 변경하지 않습니다. 기존 공간 외곽과 통로는 검토 가정입니다.
